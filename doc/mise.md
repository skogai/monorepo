# mise in this repository

How the mise configuration is laid out: environments, `conf.d` fragments, and the SkogAI plugin. Everything here was run with mise 2026.11.5; the commands and results are in the [evidence](../.skogai/tests/2026-11-11-mise-envs-plugin.md).

## Files

| Path | Loaded | Holds |
|---|---|---|
| `.miserc.toml` | First, before any other config | The default environment and discovery settings. |
| `mise.toml` | Always | Monorepo roots, tools, and tasks. |
| `mise.lock` | With `mise.toml` | Locked tool versions, URLs and checksums. Generated by `mise lock`. |
| `.config/mise/conf.d/<name>.toml` | Always | Shared fragments. None exist yet. |
| `.config/mise/conf.d/<name>.<env>.toml` | When `<env>` is selected | Fragments for one environment. |
| `mise.local.toml`, `mise.<env>.local.toml`, `.miserc.local.toml` | As their shared counterparts | Personal overrides. Ignored by Git. |

Within the checkout, later wins: `conf.d` fragments, then `mise.toml`, then environment fragments, then `mise.local.toml`. Fragments load in alphabetical order. A `conf.d/<name>.local.toml` fragment loads and is ignored by Git, but an environment fragment overrides it, so put personal overrides in `mise.local.toml`.

## Environments

An environment is a name that selects extra config files. `.miserc.toml` sets the default:

```toml
env = ["skogai"]
env_conf_d = true
```

`env_conf_d = true` makes mise read the part after the first dot in a fragment name as an environment. Without it every fragment loads for every environment. For that reason, do not use dots in a fragment's own name: write `node-tools.toml`, not `node.tools.toml`.

| Environment | Select with | Adds |
|---|---|---|
| `skogai` | nothing, it is the default | The install source of the `skogai` plugin: `https://github.com/skogai/mise-plugin` at a pinned commit. |
| `develop` | `mise -E develop …` | The `skogai-develop` plugin, linked to the `mise-plugin` submodule, and the `//:plugin:link` task. |
| `t3` | `mise -E t3 run` | Local T3 playground and interactive picker; see [T3 guide](t3-cli.md#repository-interactive-playground). |
| none | `MISE_ENV= mise …` | Nothing. The `skogai` plugin still loads once it is installed. |

`-E` and `MISE_ENV` replace the default, they do not add to it. `mise -E develop` loads `develop` only. To combine, list both: `mise -E skogai,develop`. The last one listed wins where they set the same thing.

`mise.toml` cannot select an environment, and selecting one sets no variables by itself.

To add an environment, add `.config/mise/conf.d/<name>.<env>.toml`. To see what a selection loads, run `mise -E <env> cfg`.

## Basic environment variables

The `skogai` plugin loads in every environment, so these are set everywhere:

| Variable | Set by | Value | Example |
|---|---|---|---|
| `SKOGAI_HOST` | plugin default | `/proc/sys/kernel/hostname`, `/etc/hostname` or `$HOSTNAME` | `skogix-workstation` |
| `SKOGAI_OS` | plugin default | `linux`, `macos`, `windows`, as in `mise.lock` | `linux` |
| `SKOGAI_ARCH` | plugin default | `x64`, `arm64` | `x64` |
| `SKOGAI_MISE_ENV` | `mise.toml` | The selected environments, comma-separated, empty when none | `skogai` |
| `SKOGAI_MONOREPO_DIR` | plugin | This checkout | |
| `SKOGAI_CONFIG_DIR` | plugin | `$XDG_CONFIG_HOME/skogai` | |

The `_.skogai = {}` directive is in `mise.toml`, and the plugin's install source is in the `skogai` environment fragment. On a fresh machine the default environment installs the plugin on first use. Before that, another environment, such as `mise -E t3` or `MISE_ENV=`, skips it with `WARN skipping env plugin skogai: it is not installed and has no source` instead of failing. Once installed, it loads there too. If the source is present but cannot be installed, mise fails, so the source stays in one fragment.

### Overriding

To replace a default, set the variable yourself. The plugin keeps a value that is already set in `mise.toml` above the directive, in the global config, or in the shell. `mise.local.toml` loads after the plugin and replaces its value:

```toml
# mise.local.toml (personal, ignored by Git)
[env]
SKOGAI_HOST = "laptop"
```

An empty value counts as unset. The [plugin README](../mise-plugin/README.md#overriding-the-defaults) has the full rules.

The plugin cannot see an environment chosen in `.miserc.toml`, so `SKOGAI_MISE_ENV` is a template in `mise.toml`. It strips spaces because `mise -E develop env` passes the name as ` develop` with mise 2026.11.5.

### Tasks

| Task | Does |
|---|---|
| `mise run env:show` | Lists every `SKOGAI_` variable mise sets here, including ones from the machine's global config. |
| `mise run env:test` | Checks that the plugin loaded, that `SKOGAI_MONOREPO_DIR` is this checkout, and that host, OS, architecture and environment are valid. It exits non-zero on failure and notes when `SKOGAI_HOST` is overridden. |
| `mise run env:context` | Prints host, platform, environment, checkout and Git commit, for an agent's start-up context. |
| `mise run env:context --trailers` | Prints the same as Git trailers (`Host:`, `Platform:`, `Mise-Env:`). |

To add the trailers to a commit:

```sh
git commit -m "subject" -m "$(mise run env:context --trailers)"
```

The plugin's own checks run in isolated mise directories with `mise run //mise-plugin:test`.

## Tools

Tools in `mise.toml` are pinned to exact versions, and `mise.lock` records the download URL, checksum and signer for each platform. To change a version:

```sh
mise lock usage@7.4.0
```

That updates both `mise.toml` and `mise.lock`. Commit them together. `mise install --locked` installs only what the lockfile lists. Which `mise` binary is the prerequisite, and where the other jdx tools come from, is decided in [ADR 0002](adr/0002-mise-binary-and-tool-source.md); the checks are in the [evidence](../.skogai/tests/2026-11-13-mise-tool-provenance.md).

## The SkogAI plugin

The plugin sets `SKOGAI_MONOREPO_DIR` and `SKOGAI_CONFIG_DIR`, and prepends the directories in its `paths` option to `PATH`. Its options are described in the [plugin README](../mise-plugin/README.md).

```toml
[env]
_.skogai = { paths = ["bin"] }
```

The two environments differ in where the plugin comes from:

- `skogai` uses the published plugin, pinned to a full commit SHA in `.config/mise/conf.d/plugin.skogai.toml`. mise clones it on first use. An abbreviated SHA is refused. Once installed, it also loads in environments that do not select `skogai`.
- `develop` adds the submodule in this checkout as `skogai-develop`, so edits to `mise-plugin/` apply at once. It runs after the published plugin, so its `SKOGAI_MONOREPO_DIR`, `SKOGAI_CONFIG_DIR` and `PATH` entries win. It keeps the host defaults the published plugin already set.

To move the pin, change the SHA in the fragment to a commit that is reachable in `https://github.com/skogai/mise-plugin`, usually the new `mise-plugin` submodule pointer, then reinstall:

```sh
mise plugins install --force skogai
```

`mise plugins update skogai` does not move an installed plugin to the pin. `mise doctor` warns when the installed plugin is at a different commit than the pin; nothing else does. The checks are in the [evidence](../.skogai/tests/2026-11-13-mise-plugin-pin.md).

A plugin link belongs to the mise data directory, not to a checkout. If two checkouts on one machine use `develop`, both get the plugin of the checkout that linked first. Run this in the checkout you are working in to point the link at it:

```sh
mise -E develop run //:plugin:link
```

## Monorepo notes kept from the earlier `mise.toml`

These were comments in the root `mise.toml`, kept here as reference. None of them is in use.

```toml
# [monorepo]
# config_roots = ["skogai", "skogix"]
# lockfile = true
#
# [monorepo.path_aliases]
# "mise_global" = "config/mise.config.toml"
#
# Shared task defaults for every project in the workspace:
# [monorepo.task_defaults.build]
# sources = ["src/**", "package.json"]
# outputs = ["dist/**"]
# cache = { enabled = true }
#
# [monorepo.task_defaults.test]
# env = { NODE_ENV = "test" }
#
# Task templates, used by a project task with `extends`:
# [task_templates."python:test"]
# run = "uv run pytest"
# tools = { python = "3.14", uv = "latest" }
# depends = ["build"]
#
# packages/api/mise.toml
# [tasks.test]
# extends = "python:test"
# run = "uv run pytest --cov"
#
# A task can depend on another project's task:
# [tasks.build]
# depends = ["//libs/shared:build", ":lint"]
```

Commands noted with them: `mise ls --local --monorepo`, `mise tasks --all`, `mise install --monorepo`. A template named by `extends` takes precedence over a root `task_defaults` entry.
