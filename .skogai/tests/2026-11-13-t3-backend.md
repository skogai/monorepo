## Findings

1. T3 allows one server per T3 home. The desktop app, a foreground `t3 serve`, an SSH-launched server and the service all compete for `~/.t3`.
2. With the service installed, the desktop app needs its own T3 home. It then still runs a local, empty backend (port 3774) and adds the service as a second environment. No desktop mode without a local backend was found.
3. The Omarchy bar plugin and the desktop app both reach the service through T3 Connect, so the backend depends on that being linked.
4. `~/.local/share/applications/t3code.desktop` is written by `omarchy-install-t3code-app`; a reinstall through Omarchy will reset the `Exec=` line.
