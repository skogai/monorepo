# Retired repos

**On 2026-11-19 the owner discontinued the seven repos on the Pathfinder retirement list. All seven are archived on GitHub (read-only, open issues and pull requests frozen with them) and none is in `mani.yaml` any more.** The decision is recorded in [doc/questions.md](../../doc/questions.md), "Decisions of 2026-11-19". Archived repos stay readable and can be unarchived; to read one, clone it directly with `git clone https://github.com/skogai/<name>`, since `mani` no longer knows it.

| Repo | What it was | Owner's note | Successor |
|---|---|---|---|
| `skogai/core` | argc control plane for the repo fleet | Old; to be remade on mise and usage | [skogai2-core](skogai2-core.md) continues the code; the remake is not started |
| `skogai/dash-skogai` | Control repository meant to hold all repo-wide data | Retired for now | [skogai2-dash-skogai](skogai2-dash-skogai.md), same stated purpose |
| `skogai/marketplace` | Claude Code plugin marketplace | Remade as `skogai-events` | [`skogai/skogai-events`](https://github.com/skogai/skogai-events), a single plugin (not yet covered here) |
| `skogai/skogai-core` | Older marketplace around the routing skill | Removed, not used | [skogai-core](skogai-core.md) is kept as the map of its `todo/` tree |
| `skogai/skogai-routing` | The routing convention, first version | Removed, not currently used | [skogai2-skogai-routing](skogai2-skogai-routing.md) |
| `skogai/skogai-nov10` | The earlier `skogai/skogai` knowledge and config hub | The earlier skogai | None; frozen with the other knowledge bases |
| `skogai/systemd` | Old systemd user services | Removed | [podman](podman.md) for services |

## Their own wikis

Four retired repos carry an OpenWiki generated in September 2026. They describe the repos as they were then and were not checked against the archived trees for this page. Read them for history and design ideas, not for current behaviour.

### core (`skogai/core/openwiki/`)

Generated by OpenWiki 0.5.2 on 2026-09-20. [skogai2-core](skogai2-core.md) carries a byte-identical copy, because it was copied from `core` on 2026-10-24. Six pages:

- `architecture/fleet-control-plane.md`: the fleet orchestration boundary, its argc command surface, dependencies and state ownership.
- `concepts/command-contracts.md`: how argc annotations define parsing, environment defaults, dependency gates and completions.
- `integrations/fleet-and-agent-tools.md`: external CLI calls, GitHub and agent credential boundaries, marketplace sync, a Codex hook probe.
- `testing/cli-validation.md`: the argc parser smoke-test contract.
- `workflows/environment-and-cli-build.md`: setup from prerequisites through argc generation.
- `workflows/work-context-preparation.md`: the intended issue and PR context pipeline for agent worktrees.

Relevant to the planned remake on mise and usage: the command contracts and the context pipeline are the parts the [unified proposal](../../doc/pathfinder-2026-11-14/03-unified-proposal.md) (U4) wanted kept.

### dash-skogai (`skogai/dash-skogai/openwiki/`)

Generated by OpenWiki 0.5.2 on 2026-09-20. It describes a control repository with no build of its own, whose work happens in target repos. The ideas not recorded anywhere else in this wiki:

- `workflows/delegated-agent-work.md`: `bin/skogai-paseo issue|task|review` turned an issue, a literal task or a PR into an isolated Paseo workspace with a background agent, with `--dry-run` and a default provider; `bin/skogai-run-issue` was the older one-shot headless Claude runner using `--permission-mode acceptEdits`, which never staged or committed.
- `workflows/fleet-worktree-context.md`: `repo workon <repo> <number>` created or switched a worktrunk branch for an issue or PR and wrote GitHub context to `tmp/context/` in that worktree.
- `concepts/routed-context-and-spec-lifecycle.md`: a route checker (`mise run check-routes`) that rejected durable Markdown no route reaches, and Spec Kit (`specify → plan → tasks → implement`).
- `operations/environment-and-validation.md` and `architecture/control-repository.md`: bootstrap, credentials and the ownership boundary.

These cover the same ground as the deferred work-order and dispatch plan (U5); the current way of working is plain issues to pull requests.

### skogai-nov10 (`skogai/skogai-nov10/openwiki/`)

Generated by Claude Code on 2026-09-19, updated 2026-09-25, when the repo was still `skogai/skogai`. It is the largest of the four (22 pages) and the best record of the reasoning behind later work:

- `decisions/decision-log.md`: the `DECISIONS.md` ledger through 2026-09-25, including the scrapped sandbox-egress epic and its lesson.
- `projects/skogfences.md`: agents as ordinary unix users with their own homes. The monorepo's [skogfences reference](../../doc/pathfinder-2026-11-14/skogfences-reference.md) and Pathfinder U2 build on it.
- `concepts/skogai-notation.md`, `concepts/generation-model-and-step-capture.md`, `concepts/config-as-namespace.md`: the `$`/`@` notation, the append-only entity model, and the skogcli config store as namespace.
- `projects/skogdiff-and-git-native-memory.md`, `projects/claude-settings-research.md`, `projects/devcontainer-egress-history.md`: research records.
- `workflows/ticket-to-agent-session.md`, `workflows/task-workflow-gptodo.md`: the issue-to-session target workflow and gptodo task handling.
- `operations/workstation-state.md`: a dated record of the workstation as rebuilt then.
