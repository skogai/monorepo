# skogai2-marketplace

**A Claude Code plugin marketplace named `skogai-marketplace` (manifest version 1.0.17) that lists one local plugin, `skogai-core`, and five plugins that live in other repos.** The repo has no build step. `marketplace.json` is generated by a script, never hand-edited, and a pre-commit hook and a GitHub workflow check it for drift. It is active: the 50 most recent commits run from 2026-10-23 to 2026-11-13, and HEAD is the skogai-core 0.10.0 release. 223 of its 288 tracked files are a read-only snapshot of the Claude Code docs.

Note the naming: the plugin `skogai-core` in this repo is a hook runtime. It is not the same thing as the repo `skogai/skogai-core` (see [skogai-core](skogai-core.md)), which is an older marketplace built around a routing skill.

## How it works

### Plugin inventory

Entries in `.claude-plugin/marketplace.json` carry only `name`, `source` and `description`. Versions live in each plugin's own `plugin.json`, so only the local plugin's version is known from this repo.

| Plugin | Source | What it does (manifest description) |
|---|---|---|
| `skogai-core` | `./plugins/skogai-core`, version 0.10.0 | Acts on Claude Code hook events, one script per event: event log, turn journal, diff state files, git steps, status line. All off by default |
| `codex` | `git-subdir` of `openai/codex-plugin-cc`, path `plugins/codex` | Use Codex from Claude Code to review code or delegate tasks |
| `context7` | `git-subdir` of `upstash/context7`, path `plugins/claude/context7` | Context7 MCP server for version-specific documentation lookup |
| `loadout` | `url` `skogai2/loadout` | Harness manager: switchable profiles, scope provenance, on/off for every harness element |
| `open-knowledge-plugin` | `url` `skogai2/open-knowledge-plugin`, `strict: false` | Author, maintain, backfill, validate, visualize and serve Open Knowledge Format bundles |
| `skogai-council` | `url` `skogai/skogai-council` | Consult several AI coding agents for other perspectives, with a streaming pane |

`renames` in the header maps `forge`, `verity` and `jetbrains-router` to `null`, which retires those names.

### Manifest generator

`scripts/generate-marketplace-json.sh` builds the manifest from three inputs: the header file, every `plugins/*/.claude-plugin/plugin.json` (written as `"source": "./plugins/<dir>"`, `:79-110`), and `external-repos.json` (`:122-203`). For each external entry it fetches the remote `.claude-plugin/plugin.json` through `gh api` when `gh` is installed, otherwise from a blobless clone (`:167-179`). A repo with no `plugin.json` is accepted when its own `marketplace.json` has a single `"./"` entry; the generator then adds `"strict": false` (`:183-198`). It rejects duplicate JSON keys (a Python check, `:32-48`) and duplicate plugin names (`:206-207`), sorts entries by name, and bumps the patch version only when content changed (`:226-235`). `--check` regenerates in memory, prints a diff and exits 1 on drift, and writes nothing (`:216-224`).

### skogai-core hook runtime (`plugins/skogai-core`)

`hooks/hooks.json` registers one command hook for each of 13 events, with no matchers: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `SubagentStart`, `SubagentStop`, `PreCompact`, `PostCompact`, `Stop`, `StopFailure`, `SessionEnd`. Each runs `${CLAUDE_PLUGIN_ROOT}/scripts/events/<Event>.sh` with the event JSON on stdin. The file also loads one function-hook module, `./register.ts`.

Shared scripts:

- `scripts/settings.sh` reads the settings. Claude Code exports each `userConfig` option as `CLAUDE_PLUGIN_OPTION_<KEY>`; `skogai_opt` falls back to the `plugin.json` default when the variable is unset (`:14-17`). It sets the shell variables `SKOGAI_ENABLED`, `SKOGAI_EVENTS`, `SKOGAI_LOG`, `SKOGAI_JOURNAL` and `SKOGAI_STATE`, resolving relative paths against the git root (`:24-36`). These are internal shell variables, not environment inputs.
- `scripts/append-json.sh` appends one row to the event log. It exits silently when `enabled` is off or the event does not match `events` (`:13-14`). It holds a `flock` on the log because hooks can fire in parallel (`:20-21`). Row shape: `{ts, event, action?, input}` where `input` is the whole hook payload (`:22-25`).
- `scripts/write-state.sh <root> <dir>` overwrites three files: `git-diff` (`git diff`), `git-diff-cached` (`git diff --cached`) and `wt-step-diff` (`wt step diff`, empty when `wt` is missing). It creates a `.gitignore` containing `*` in the directory.
- `scripts/git-steps.sh <stop|prompt> <root> [path...]` runs, in order: a commit of only the given paths with message `skogai-core: journal` (`:23-32`), `git add -A` when `stage_on_<event>` is on, `wt step commit` when `commit_on_<event>` is on and the tree is dirty, and `wt merge --no-remove` when `merge_on_<event>` is on. It prints what ran as a comma-separated list for the log. Failed `wt` steps are logged, not fatal.

What each event does:

| Event | Script behaviour | Writes |
|---|---|---|
| `SessionStart` | Writes state files if `write_state` is on, then logs with action `wrote state` | state dir, log row |
| `UserPromptSubmit` | Runs the `*_on_prompt` git steps, writes state files if `write_state` is on, then logs what ran | git index/commits, state dir, log row |
| `Stop` | If `journal` is on, appends the turn to the journal and commits only that file. Runs the `*_on_stop` git steps. Writes state files if `write_state` is on. Logs the combined action | journal, git index/commits, state dir, log row |
| The other 10 events | One line: `exec append-json.sh` | log row only |

The `Stop` journal entry (`scripts/events/Stop.sh:36-59`) is built from the log, not the transcript. `turn_rows` reads the log backwards to the turn's `UserPromptSubmit` row and keeps rows with the same `prompt_id` and no `agent_id` (`:28-34`). The entry has a heading `## <date time> · turn <first 8 chars of prompt_id>`, the user prompt as a blockquote, the hook payload's `last_assistant_message`, and one line per `PostToolUse` or `PostToolUseFailure` row. So the journal needs `UserPromptSubmit` and `PostToolUse*` to be logged. The log itself is never committed. Outside a git repository, `Stop` only logs.

`hooks/register.ts` only drives the status line. It registers nothing unless both `enabled` and `status_line` are true (`:34`). It hooks the native events `session.start`, `turn.start`, `tool.call` and `turn.complete`, calls `next(e)` first, then runs `tail -n1` on the log and shows `hook: <event>` (`:16-27`, `:41-60`). A comment at `:37-39` records that `classic.*` hooks never run for user-installed mods.

Settings (`userConfig` in `.claude-plugin/plugin.json`):

| Key | Default | Effect |
|---|---|---|
| `enabled` | `false` | Master switch. Off: no log, journal, state files, git steps or status line |
| `events` | `*` | Space-separated event names or globs (such as `Post*`) to log |
| `log_path` | `.skogai/logs/skogai-core/log.jsonl` | Event log, relative to the git root or absolute |
| `journal` | `false` | On `Stop`, append the turn and commit only the journal |
| `journal_path` | `.skogai/journal.md` | Journal file |
| `write_state` | `false` | Write the three diff files on `SessionStart`, `UserPromptSubmit`, `Stop` |
| `state_dir` | `.skogai/tmp` | Where the diff files go |
| `status_line` | `false` | Show `hook: <event>` |
| `stage_on_stop`, `stage_on_prompt` | `false` | `git add -A` |
| `commit_on_stop`, `commit_on_prompt` | `false` | `wt step commit`, skipped when the tree is clean |
| `merge_on_stop`, `merge_on_prompt` | `false` | `wt merge --no-remove` |

`DIFF-AS-CONTEXT.md` gives the reason for this design: `git diff --cached` plus the next message is meant to be the full context of a turn. This repo applies it to itself: `.skogai/CLAUDE.md` imports `tmp/git-diff` and `tmp/git-diff-cached`.

### Config CLIs

`scripts/config/argc.sh` and `scripts/frontmatter/argc.sh` were copied out of skogai-runner. They are not used by the plugin. `config` has `get`, `set`, `unset`, `list`, `env` and `files`, and folds layers in this order: `config:` in each `module.md`, then git-config files in `SKOGAI_SYSTEM_DIR` (default `/etc/skogai`), `SKOGAI_CONFIG_DIR` (default `~/.config/skogai`) and `SKOGAI_LOCAL_DIR` (default `.skogai` at the git root), then `module.local.md`, then `--file` frontmatter and its `.local.md`, then `SKOGAI_*` environment variables (`scripts/config/module.md`). Key `stage.on-stop` maps to `SKOGAI_STAGE_ONSTOP`. Modules are found through `SKOGAI_MODULE_PATH`.

## How to use it

Everything below is as the repo documents it; nothing was run.

- Install the plugin: `/plugin install skogai-core --marketplace skogai2/marketplace` (plugin README).
- Configure it: `/plugin configure skogai-core@skogai-marketplace` or `/config`, then `/reload-plugins`. Values are stored under `pluginConfigs` in the user's `~/.claude/settings.json`, so they apply to every project. With `--plugin-dir` there is no dialog; set `pluginConfigs["skogai-core@inline"].options` by hand.
- Develop it: `claude --plugin-dir plugins/skogai-core`, `claude plugin validate plugins/skogai-core`, and `plugins/skogai-core/tests/run.sh`, which feeds sample hook rows through the scripts in a throwaway git repo. The scripts need `bash`, `jq`, `git` and `flock`; the git steps and `wt-step-diff` also need worktrunk's `wt`.
- Add a plugin: the `/add-plugin` skill, or edit `external-repos.json` or create `plugins/<name>/.claude-plugin/plugin.json`, then run `scripts/generate-marketplace-json.sh`. The script needs `jq` and `python3`, and `gh` or `git` with network access for external entries.
- Enable the drift guard locally: `git config core.hooksPath scripts/git-hooks`.
- Commits go directly to `master`.
